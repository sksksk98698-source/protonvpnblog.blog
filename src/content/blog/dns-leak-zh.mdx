## 什么是 DNS 泄漏？为什么它会彻底摧毁你的隐私防线？

许多用户以为只要开启了代理软件，自己的所有网络痕迹就彻底隐形了。然而，**DNS 泄漏（DNS Leaks）**是翻墙领域最常见、也最隐蔽的“隐私致命漏洞”。

### 1. DNS 泄漏的攻击与暴露机理

在默认网络配置下，当你输入 `www.google.com` 时：
1. 操作系统并不会直接建立 TCP 连接，而是必须先通过 UDP 53 端口向你宽带运营商（如中国电信、联通、移动）的 Local DNS 服务器询问目标 IP。
2. 此时，你的代理客户端若未配置严格的 DNS 劫持接管，这个明文查询请求就会**绕过代理通道，直接从本地真实家庭宽带物理网卡发出**。
3. 本地运营商的审计网关在 1 毫秒内就能完整记录：**“某年某月某日某时，你所在小区的真实家庭宽带 IP，发起了解析敏感海外域名的请求”**。

这不仅导致目标海外域名遭到防火墙的 DNS 污染劫持（返回错误的 IP 导致网页打不开），更让你的真实网络身份彻底赤裸裸地暴露无遗。

## 杜绝 DNS 泄漏的三大核心技术手段

### 1. 部署 DoH（DNS over HTTPS）强加密解析

传统 DNS 使用明文 UDP 53 端口传输，任何人均可在中间链路进行监听与伪造。而 **DoH（DNS over HTTPS）** 将 DNS 查询请求封装在正规标准的 HTTPS TLS 加密流量中（TCP 443 端口），其报文特征与普通浏览网页完全一致，中间路由器和运营商绝对无法解密或篡改查询内容。

推荐配置的纯净 DoH 服务器端点：
- **阿里公共纯净 DNS**：`https://223.5.0.5/dns-query`
- **腾讯 DNSPod 纯净端**：`https://1.12.12.12/dns-query`
- **Cloudflare 隐私安全端**：`https://1.1.1.1/dns-query`
- **Google 官方权威端**：`https://8.8.8.8/dns-query`

### 2. 启用客户端 Fake-IP 模式消除本地解析

在基于 Mihomo (Clash.Meta) 或 Sing-box 内核的现代客户端中，强烈建议将 DNS 运行模式设置为 **`fake-ip`**：
- 当应用程序发起查询时，客户端在本地虚拟内存中瞬间下发一个 `198.18.0.0/16` 伪地址，完全阻断了向公网发送明文 DNS 的物理行为。
- 当应用程序向该假 IP 发送数据包时，客户端拦截该数据报文，还原出真实域名，并直接将域名封装进代理通道，由境外的 IEPL 专线出口服务器在远端完成纯净解析。

### 3. 封堵 WebRTC 真实公网 IP 嗅探漏洞

现代浏览器（Chrome、Edge、Firefox）为了支持网页视频会议与 P2P 音视频通信，内置了 WebRTC 协议。
黑客与恶意追踪网站可以通过在网页中植入一段简单的 JavaScript 脚本，强制向公共 STUN 服务器发起连接测试。
若浏览器未做安全限制，**你的真实电信/联通家庭公网 IP 将直接穿透代理网关被网页脚本捕获**！

> [!IMPORTANT] WebRTC 泄漏自测与防护准则
> 1. 访问安全检测站点（如 `browserleaks.com/webrtc`）。
> 2. 检查输出报告中的 `Public IP Address`。如果显示的是你的真实家庭宽带 IP（而非代理节点的境外 IP），即代表存在严重泄漏。
> 3. 防护方案：在 Chrome / Edge 中安装 WebRTC Control 扩展，或在内核配置中启用强制 UDP 全量代理分流。
